# P2-2 — YAML Export — Design

**Status:** Draft v1 · **Date:** 2026-05-02 · **Phase:** 2 (Polish & Release) · **Sizing:** S

## Goal

Surface the dashboard config that Lovelacer would apply to Home Assistant as a downloadable YAML file. Users can save it to git for version control, use it as a starting point for ui-mode dashboards, share it for support, or audit what's about to be applied before clicking Apply.

**Acceptance criteria** (from ROADMAP.md):

- Downloaded file is valid YAML.
- Equivalent to applied storage config.
- Tested against `ha core check`.

## Context

Phase 1 produced `LovelaceConfig` — a fully-typed TypeScript object that the apply route hands to Home Assistant via the storage-mode WebSocket API. Until now there was no way for users to read or persist that config outside of HA's own storage. P2-1 (re-analysis diff view) just shipped, leaving every preview response carrying the same `LovelaceConfig` plus a `diff: DiffResult | null`.

P2-2 closes the export gap with a single new endpoint and a button on the Preview screen. No new persistence — the YAML reflects the current preview output (what would be applied right now) rather than the last-applied snapshot, matching user intuition ("download what I'm looking at"). The snapshot-as-source-of-truth case is a future feature.

The `yaml@^2.6.0` package is already a direct dependency of `@lovelacer/generator`, used today by fixture loaders and dev scripts. It hasn't yet been wired into the runtime generator output — the package's `index.ts` even has a comment anticipating this ticket: `Phase 2: yaml-export.ts (proper YAML serialization)`.

## Architecture & data flow

Three pieces, all small:

1. **YAML serializer** (`packages/generator/src/yaml-export.ts`). Pure function. Input: a `LovelaceConfig` and optional `{ version, generatedAt }`. Output: a string with the minimal header + YAML body. No IO, no awareness of routes or HTTP. Lives in `@lovelacer/generator` because it's the package's job to transform the config representation, and the `yaml` dep is already there.

2. **New route** (`packages/server/src/routes/export.ts`). `GET /api/export.yaml`. Calls `runPreview()` internally — the same function the preview route uses — to get the current `LovelaceConfig`, runs it through `configToYaml()`, returns with `Content-Type: application/yaml; charset=utf-8` and `Content-Disposition: attachment; filename="<dashboardUrlPath>.yaml"`. Errors mirror the preview route: 503 on HA-not-connected, 500 on pipeline failure.

3. **Frontend button** in `DashboardPreview.vue`. Plain `<a href="/api/export.yaml" download>Download YAML</a>` styled as a secondary button. Renders inside the existing `v-if="config.views.length > 0"` gate, right-aligned next to the "Will create N views" header. Zero JavaScript — the browser handles the download natively.

The export route doesn't need its own snapshot — it serializes the current preview output. If the user wants the last-applied dashboard, the snapshot store already has the JSON (out of scope for P2-2).

## YAML serializer

New file `packages/generator/src/yaml-export.ts`. Single export, single function.

```ts
import { stringify } from 'yaml'
import { GENERATOR_VERSION } from './index.js'
import type { LovelaceConfig } from './lovelace-config.js'

export interface ConfigToYamlOptions {
  /** Tool version printed in the header. Defaults to GENERATOR_VERSION. */
  version?: string
  /** Generation timestamp. Defaults to `new Date()` — caller can pin for tests. */
  generatedAt?: Date
}

/**
 * Serialize a LovelaceConfig as a YAML string with a minimal header
 * comment. Stable output: same input + same options → byte-identical
 * string (modulo `generatedAt` if not pinned).
 */
export function configToYaml(config: LovelaceConfig, options?: ConfigToYamlOptions): string {
  const version = options?.version ?? GENERATOR_VERSION
  const generatedAt = (options?.generatedAt ?? new Date()).toISOString()
  const header =
    `# Generated by Lovelacer v${version} on ${generatedAt}\n` +
    `# This file is regenerated each time you click Apply or Download YAML.\n` +
    `# Manual edits to this file will NOT be preserved on the next run.\n` +
    `\n`
  const body = stringify(config, {
    indent: 2,
    lineWidth: 0,
    minContentWidth: 0,
  })
  return header + body
}
```

`lineWidth: 0` is the load-bearing option. By default the `yaml` package wraps long string scalars at 80 columns, which would break entity ids like `light.kitchen_under_cabinet_strip_with_a_very_long_name` across lines — visually messy and harder to grep. `minContentWidth: 0` keeps short scalars compact (no enforced minimum width).

The header is exactly four lines (three comment lines + a blank line). The "manual edits will not be preserved" warning is the load-bearing line — without it, somebody will edit the file by hand, re-run Lovelacer, and lose their work.

Re-exported from `packages/generator/src/index.ts`:

```ts
export { configToYaml } from './yaml-export.js'
export type { ConfigToYamlOptions } from './yaml-export.js'
```

## Route

New file `packages/server/src/routes/export.ts`.

```ts
import type { FastifyInstance, FastifyPluginAsync } from 'fastify'
import type { HaClient } from '@lovelacer/ha-client'
import { configToYaml } from '@lovelacer/generator'
import type { OverrideStore } from '../storage/override-store.js'
import type { AppliedSnapshotStore } from '../storage/applied-snapshot-store.js'
import { runPreview } from '../pipeline.js'

export interface ExportRouteOptions {
  ha: HaClient
  overrides: OverrideStore
  appliedSnapshot: AppliedSnapshotStore
  /** Filename suggested via Content-Disposition. Matches dashboardUrlPath. */
  dashboardUrlPath: string
}

const SAFE_FILENAME = /^[a-zA-Z0-9_-]+$/

export const exportRoute: FastifyPluginAsync<ExportRouteOptions> = async (app, opts) => {
  app.get('/api/export.yaml', async (req, reply) => {
    if (!opts.ha.isConnected()) {
      return reply
        .code(503)
        .send({ error: 'ha_unavailable', message: 'Home Assistant connection not ready' })
    }
    try {
      const preview = await runPreview(opts.ha, opts.overrides, opts.appliedSnapshot)
      const yaml = configToYaml(preview.config)
      const safeStem = SAFE_FILENAME.test(opts.dashboardUrlPath)
        ? opts.dashboardUrlPath
        : 'lovelacer-home'
      return reply
        .code(200)
        .header('Content-Type', 'application/yaml; charset=utf-8')
        .header('Content-Disposition', `attachment; filename="${safeStem}.yaml"`)
        .send(yaml)
    } catch (err) {
      req.log.error({ err }, 'export failed')
      return reply.code(500).send({ error: 'export_failed', message: String(err) })
    }
  })
}
```

`SAFE_FILENAME` defends against a hypothetical future code change that loosens HA's storage-mode validation of `dashboardUrlPath`. Today HA's schema already enforces URL-safe strings, but embedding user-influenced strings into HTTP headers is the kind of thing where defense-in-depth is cheap.

The route reuses `runPreview()` so the YAML reflects the same config the user just saw in the Preview screen. The invite gate already 403s `/api/export.yaml` like every other `/api/*` path that isn't `/api/health` or `/api/invite` — no special-casing needed.

Wired into `packages/server/src/app.ts` alongside the existing routes (registration order: `inviteRoute`, `analyzeRoute`, `previewRoute`, `applyRoute`, **`exportRoute`**, `overridesRoute`):

```ts
await app.register(exportRoute, {
  ha: opts.ha,
  overrides: opts.overrides,
  appliedSnapshot: opts.appliedSnapshot,
  dashboardUrlPath: opts.dashboardUrlPath,
})
```

`CreateAppOptions` already has all the fields this route needs from prior tickets — no new wiring.

## Frontend

Updated `packages/web/src/components/DashboardPreview.vue`. The `<script setup>` block is unchanged. The template gains a flex header wrapping the existing title + a new download link:

```vue
<template>
  <section v-if="config.views.length > 0">
    <div class="mb-3 flex items-center justify-between">
      <h3 class="text-sm font-medium text-stone-700">
        Will create {{ config.views.length }} dashboard
        {{ config.views.length === 1 ? 'view' : 'views' }}
      </h3>
      <a
        href="/api/export.yaml"
        download
        data-testid="export-yaml-link"
        class="rounded border border-stone-300 bg-white px-3 py-1 text-xs font-medium text-stone-700 hover:bg-stone-50"
      >
        Download YAML
      </a>
    </div>
    <ul class="flex flex-wrap gap-2">
      <!-- unchanged -->
    </ul>
  </section>
</template>
```

Notes:

- `download` (no value) lets the server's `Content-Disposition: filename=...` win, which means the file is named after the addon's own `dashboardUrlPath` — not hardcoded in the SPA.
- Right-aligned next to "Will create N views" keeps the link visually associated with the dashboard preview, not floating in space.
- `border-stone-300 bg-white text-stone-700` is the secondary-button family already used elsewhere (matches the "Done — start over" button in `ApplyBar.vue`).
- `data-testid="export-yaml-link"` for the integration test.

The link only renders when `config.views.length > 0` — same gate the existing component uses. Before the user analyzes, the section is hidden.

## Edge cases & error handling

- **HA disconnected at click time.** Route returns `503 ha_unavailable` with a JSON body. Browser treats this as a failed download (no file saved, browser shows its own "couldn't download" UX). The user sees the existing `<HealthBar>` already at the top of the page indicating the disconnect, so the failure is self-explanatory. No new in-SPA toast needed.

- **Pipeline failure mid-export.** Returns `500 export_failed`. Same browser behavior — failed download, no in-SPA notification. Logged via `req.log.error` for ops visibility.

- **YAML stringify failure.** Realistically can't happen on a `LovelaceConfig` (plain objects, strings, numbers, arrays — no circular refs, no functions). `yaml.stringify` will not throw on this shape. Wrapped in the same try/catch anyway for belt-and-suspenders.

- **Massive configs.** A 500-entity, 14-room install produces a few hundred KB of YAML. Browser native download handles megabytes without issue. No streaming needed.

- **Filename safety.** `dashboardUrlPath` is validated by HA's storage-mode `lovelace/dashboards/create` schema. The route runs `dashboardUrlPath` through `SAFE_FILENAME` (`/^[a-zA-Z0-9_-]+$/`) before embedding. If invalid, falls back to `lovelacer-home`. One-liner, harmless even when the input is already valid.

- **HEAD requests.** Fastify's GET handler responds to HEAD automatically (returns headers only). Browsers occasionally pre-flight downloads with HEAD. No additional work needed.

- **Re-export consistency.** Two clicks within seconds produce the same YAML body modulo the `generatedAt` header timestamp. That's intentional — the timestamp reflects when the YAML was generated, not when the dashboard was applied. If the user wants a stable reference, they apply (snapshots the config) then export (matching content, fresh timestamp).

- **Invite gate.** The gate hook 403s `/api/export.yaml` like every other `/api/*` path. The download button only renders inside `DashboardPreview.vue`, which is inside the analyze section, which is gated behind the invite UI — so the user can't reach the link until they've accepted an invite. No bypass risk.

## Testing strategy

**`packages/generator/src/__tests__/yaml-export.test.ts`** — pure-function tests:

- Empty config (`{ title: '...', views: [] }`) → returns header + valid YAML with `views: []`.
- Roundtrip via `yaml.parse` — serialize a config with multiple views, parse the result, deep-equal to the original. Pins the contract that the output is real YAML.
- Header pinned: with `version: 'test-1.2.3'` and `generatedAt: new Date('2026-05-02T17:00:00Z')`, assert the first three lines exactly. Locks the header format.
- Long entity ids stay on one line: serialize a config with `light.kitchen_under_cabinet_strip_with_a_very_long_name`, assert the entity id appears exactly once and not split. Pins `lineWidth: 0`.
- Default options: omit `version`/`generatedAt`, assert the body still parses and the header has the package version + a recent ISO timestamp.

**`packages/server/src/__tests__/routes/export.test.ts`** — `app.inject`-based route tests:

- HA disconnected → `503 ha_unavailable`.
- Happy path → 200, `Content-Type: application/yaml; charset=utf-8`, `Content-Disposition: attachment; filename="lovelacer-home.yaml"`. Body parses as YAML and contains the expected `title` + `views[]` from the fixture analysis.
- Pipeline failure (mock `getEntityRegistry` to throw) → `500 export_failed`.
- Custom `dashboardUrlPath` (`'my-dash'`) → filename in Content-Disposition is `"my-dash.yaml"`.
- Invalid `dashboardUrlPath` (e.g., contains `..` or quotes) → falls back to `"lovelacer-home.yaml"`.
- Threads `appliedSnapshot: makeAppliedSnapshot()` like every other route test (carried from P2-1).

**`packages/web/src/__tests__/components/DashboardPreview.test.ts`** — extends existing tests:

- New case: when `config.views.length > 0`, `[data-testid="export-yaml-link"]` is rendered with `href="/api/export.yaml"` and the `download` attribute present.
- Existing "no link when empty config" implicitly covered by the surrounding `v-if`.

**Manual smoke (per ROADMAP DoD).**

Run dev stack, analyze, click "Download YAML":

1. File downloads as `lovelacer-home.yaml` (or whatever `dashboardUrlPath` is set to).
2. Open in editor — header comment present, valid YAML structure.
3. Run `ha core check` against the file (or copy contents into HA's `lovelace.yaml` and reload) — passes.

That's the AC.

## Out of scope (deferred)

- **Export the last-applied snapshot config.** P2-1's `AppliedSnapshotStore.config` already has it. A future ticket can add `?source=snapshot` (or a separate route) when there's a clear use case.
- **Diff-aware export.** Including the diff in the YAML header (e.g., "5 changes since last apply") creates noise for the common case and complicates re-export consistency. Skip.
- **Multi-format export** (JSON, Markdown summary). Out of scope; YAML is the dashboards/import format HA expects.
- **Server-side filename customization beyond `dashboardUrlPath`.** Users who want a different filename can rename after download.
